# 出行预订交互原型参考

来源：`D:/WorkBuddyData/workbuddy/2026-08-26-13-24-13/出行预订App-交互原型.html`

原型文件：`travel-booking-app-interaction-prototype.html`

## 用途

这是一个外部制作的出行预订交互参考原型，保存于仓库中，方便后续在其他电脑继续查看和讨论。它不是当前 SchatPhone 运行时页面，也不代表项目已经接入真实交通预订、支付或出票服务。

## 可借鉴部分

- 首页把交通方式、出发地、目的地、日期和筛选条件放在一个明确的搜索起点中。
- 车次/航班结果使用“编号、出发到达、耗时、余票/价格”进行横向比较。
- 详情页将乘客、座位/舱位、费用摘要和最终动作分层展示。
- 行程页区分即将出行、全部和已完成，并把提醒状态放在行程卡上。
- 消息页把晚点、出票、临近提醒和账户安全放在同一条出行消息流中。
- 首页、行程、消息、个人四个高频入口的导航结构可作为 VIA 的信息架构参考。

## 当前不能直接照搬的部分

- 真实订单、支付、出票、二维码检票、会员、优惠券和账户支付管理。
- 自动生成有效车票、座位、余票、晚点结果或真实平台通知。
- 将本地出行意向直接写成 Calendar、Agenda Journey、Map Journey 或 Wallet 的正式记录。
- 将“支付成功”“已出票”等文案用于当前 S1 壳子。

## 适配方向

这个原型最适合先服务于 `VIA / 联程`，即城际交通比较和本机出行意向草稿。它的一部分行程展示也可以被 `ROAM / 漫泊` 借鉴，但 ROAM 仍应保持旅行住宿身份，不要变成第二个交通票务 App。

推荐的 S1 适配语义是：

```text
交通选项 → 比较结果 → 出行意向草稿 → 返回 Calendar 确认（未来）
```

其中“订单确认、支付、出票、检票”属于后续明确批准的 S2/S3 工作，不由这份原型自动授权。

## 视觉观察

原型的优点是信息层级清楚、结果比较效率高、状态较完整；需要适配 SchatPhone 时，应保留它的任务结构，重新建立 VIA 自己的视觉语言，避免直接复制“珊瑚红＋青绿色＋大卡片”的品牌外观。
