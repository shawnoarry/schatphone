# Shopping 六店品牌网店 UI 装修与素材需求指南

Updated: 2026-08-19

Status: `USER-REQUESTED DESIGN DIRECTION / PLANNING ONLY / NOT IMPLEMENTED`

本文件定义 Shopping 六个独立网店的目标页面结构、品牌装修语言、动效语法与完整素材需求。它是视觉与内容生产指南，不是第二路线图，不表示页面、商品数据、营销活动或素材已经实现、获批或接入。`docs/roadmap/TODO_ROADMAP.md` 仍是唯一执行队列；任何实现、生图和数据扩展都必须先作为明确切片进入当前路线图。

本指南扩展 `docs/pm/commerce-finance-and-assets/SHOPPING_STOREFRONT_PRODUCT_AND_IMAGE_ASSET_BRIEF.md`。原 brief 的 72 张商品主图、6 张 Hero 和 12 张 Banner 是本指南完整素材库中的最低子集，不再足以单独代表“店铺装修完成”。

## 1. 目标体验

Shopping 不是六个换色后的商品列表，而是六个可独立打开、具有真实商业内容密度和品牌叙事的线上店铺 App：

1. Coupang 是强调搜索、履约、日常复购和高密度优惠发现的综合商城。
2. 29CM 是以专题、编辑内容、设计说明和克制选品组织商品的生活方式平台。
3. Kurly 是以晨间配送、冷链、新鲜度、产地故事和家庭餐桌组织内容的生鲜平台。
4. WORKSOUT 是由上新、品牌、造型、Lookbook 和限量企划驱动的多品牌时装店。
5. IKEA Korea 是由房间、生活问题、搭配方案和空间规划驱动的家居品牌店。
6. OLIVE YOUNG 是由榜单、功效、肤质/状态、品牌活动和护理步骤驱动的美妆护理平台。

完成后的用户感受应当是：进入不同店铺时，首屏内容、浏览节奏、媒体比例、货架组织和页面动效都明显变化；进入购物袋、结账和订单时，又能获得稳定、可信、可预测的交易体验。

| 29CM | <https://www.29cm.co.kr/> | 编辑型首页、专题封面、品牌/设计叙事、留白与内容策展 | 官方专题、品牌合作、模特图、商品图和杂志文案 |

| WORKSOUT | <https://worksout.co.kr/> | Drop 文化、品牌切换、Lookbook、限定企划与时装媒体 | 真实品牌目录、联名、抽签活动、Logo 和人物摄影 |
| IKEA Korea | <https://www.ikea.com/kr/ko/> | 房间优先、场景搭配、空间解决方案、尺寸与组装信息 | 官方产品造型、系列名、房间摄影、说明书和价格 |

参考只用于提取信息架构、内容密度、页面节奏和商业认知。所有商品、包装、活动、价格、编辑文案与媒体都必须是 SchatPhone 虚构内容；不得暗示官方合作、官方商城或真实库存。

### 3.2 不可变业务边界

- 六店稳定 `serviceKey`、模板 ID 和 canonical route 不变。
- Home Shopping folder 仍只是 Native System launcher；打开子项后，选中的店铺成为完整视觉 owner。
- 商品、收藏、购物袋、结账、订单、物流与分享记录继续按 `serviceKey` 隔离。
- 六店可以复用 Shopping Store、schema、报价、备份和订单执行机制，但不得复用同一套首页组合。
- 不新增可见的第七个 Shopping hub，不提供店内跨店切换、跨店购物袋或混合结账。
- App Store 只管理入口和门面字段，不能拥有或修改 Shopping 商品和交易真相。
- Map 场景锚点是只读背景语义，不是官方门店、库存或配送地址声明。

## 4. 信息架构与页面深度

### 4.1 深度模型

| 深度 | 用户问题 | 页面/容器 | Shopping 示例 |
| --- | --- | --- | --- |
| L0 概览 | 这里今天有什么值得看？ | 店铺 Home | Hero 轮播、分类入口、专题、榜单/编辑精选、推荐货架 |
| L1 聚焦 | 这件商品或这个专题具体是什么？ | 独立详情 route；必要时使用保留上下文的 bottom sheet | 商品详情、快速选择规格、活动预览、房间热点商品组 |
| L2 管理 | 我要找到、筛选或回看某类内容 | 独立全量页面 | 搜索结果、分类、集合、收藏、最近浏览、订单和物流 |
| L3 执行 | 我要完成一次购买或明确操作 | 专用流程页 | 规格确认、购物袋、结账、订单后续、商品管理工作台 |

### 4.2 页面族

每店至少规划以下页面族。路径形式是后续实现建议，不是本轮冻结的 route 合同。

| 页面族 | 必须具备的内容 | 返回原则 |
| --- | --- | --- |
| Home | 品牌首屏、搜索、4 个 Hero campaign、至少 5 种内容模块、最近浏览/服务入口 | 返回 Home 原页面索引 |
| Category / Collection | 标题媒体、筛选、排序、商品流、相关专题 | 返回原 Home 模块和滚动位置 |
| Campaign / Editorial | 专题 Hero、故事段落、商品集合、明确 CTA | 返回原海报或广告 rail |
| Product Detail | 5 个产品媒体槽、价格/报价、状态、规格、长详情、相关搭配 | 返回原货架、搜索或专题位置 |
| Search | 最近搜索、建议、结果、筛选、无结果恢复 | 清空后回到店铺 Home |
| Saved / Recently Viewed | 收藏、最近浏览、重新进入来源 | 保留当前店铺隔离 |
| Bag / Checkout | 商品行、数量、报价、配送/领取选择、确认 | 保持高频操作稳定，拒绝装饰干扰 |
| Orders / Order Detail / Logistics | 状态、时间线、订单媒体、物流和来源返回 | 订单真相继续由 Shopping 所有 |
| Manager | 自定义商品与店铺内容维护 | 与消费者浏览分离，仅明确管理入口进入 |

### 4.3 导航规则

- 手机底部导航最多 5 项；搜索可以位于顶栏，不为凑满导航重复入口。
- 所有店铺必须在两次点击内到达收藏、购物袋和订单。
- 品牌可以改变导航标签和构图，但同一语义必须使用相同图标和可访问名称。
- Product、Campaign、Category 均可深链接；浏览返回必须恢复原筛选、rail 位置和滚动上下文。
- 购物袋、结账、订单等高后果页面不自动播放广告，不用循环背景和滚动劫持。

## 5. 共享装修系统

共享系统只标准化交易语义、可访问性和尺寸，不统一六店构图。

### 5.1 首屏

- 第一视口必须同时出现店铺身份、搜索或主要发现入口、Hero 的主要内容，以及下一模块的可见线索。
- Hero 不得把整个手机首屏完全占满；在 `393 x 851` 视口应露出下一层分类、利益点或专题标题。
- Hero 默认 4 个 campaign；超过 5 个时应拆成专题 rail，避免无尽轮播。
- 每个 campaign 必须有明确主题、目标商品集合、CTA、有效期策略和无媒体 fallback。
- 品牌 Logo 是识别元素，不作为占据半屏的装饰水印。

### 5.2 广告与海报容器

| 容器 | 用途 | 交互 |
| --- | --- | --- |
| Hero carousel | 全店重点活动或品牌季节主题 | 手势、箭头、指示器、暂停；自动轮播间隔 5-7 秒 |
| Rolling ad rail | 配送利益点、主题集合、品牌周和服务信息 | 横向 snap，一次露出 1.15-1.4 张，暗示可继续滑动 |
| Portrait poster rail | 视觉主导的新品、Lookbook、房间、护理主题 | 竖版海报滚动；点击进入完整专题页 |
| Editorial banner | 有标题和内容说明的集合入口 | 图片与代码文字共同组成，不把长文烘焙在图中 |
| Slim campaign strip | 短利益点、服务或分类活动 | 不自动滚动长文字，不制造不可暂停 marquee |
| Story band | 专题长页中的章节媒体 | 随页面滚动出现，保持上下章节连续性 |

### 5.3 商品卡

商品卡只承担快速识别和进入，不代替详情页：

- 主图、商品名、当前展示价、真实状态、收藏与一个明确进入/加购动作；
- 支持列表、两列、横向 rail 和编辑大卡等不同变体；
- 商品卡高度和图片比例稳定，标签出现时不能推挤价格与操作；
- 快速加购只适用于不需要规格选择的商品；需要尺寸、颜色或组合时进入 L1 选择；
- 不在卡片上堆叠完整描述、所有标签、物流说明和架构边界文案。

### 5.4 商品详情页

每个内置商品目标至少有 5 个产品媒体槽：

1. `main`：识别商品的标准主图；
2. `detail`：结构、材质、纹理、食材或质地近景；
3. `use`：真实使用方式或功能关系；
4. `context`：对应店铺语法的生活方式/空间/造型场景；
5. `spec`：尺寸、成分、保存、搭配或规格信息，优先原生 SVG/代码图表。

详情页面固定信息顺序：媒体识别、标题/价格/状态、必要规格、主要 CTA、核心卖点、长详情、规格与服务、关联内容。不同品牌可以改变长详情叙事和媒体比例，但不能把价格、状态和购买动作藏在装饰之后。

### 5.5 专题长页

每店首轮至少规划 3 个可完整打开的 Campaign / Editorial 页面。每页需要：

- 1 个页面 Hero；
- 3 个故事段落媒体；
- 1 个商品集合；
- 1 个明确返回与 CTA；
- 移动和宽屏的独立构图检查；
- 无效活动、商品缺失和图片加载失败状态。

### 5.6 交易与订单页面

- 保留品牌色、字体角色和轻量材质，但页面结构以可预测和准确为先。
- 商品行始终显示可识别缩略图；订单详情不得退回纯文字 ID 列表。
- 价格、报价、配送、库存、退款和订单状态只能来自真实业务数据。
- 结账前不插入自动轮播、倒计时、全屏视频或遮挡提交操作的装饰。
- 支付成功可以有一次品牌化完成反馈，持续时间不超过 900ms，随后立即显示订单真相。

## 6. 商业真实性与内容合同

真实感来自完整信息和内容组织，不来自伪造数字。

| 常见网店元素 | 没有对应数据合同时的处理 |
| --- | --- |
| 销量榜、热卖第 1 | 改为“编辑精选”“本周主题”或真实排序，不伪造销量 |
| 星级、评价数量、问答 | 暂不显示；先建立 review/Q&A 所有权和持久化合同 |
| 原价、折扣率、优惠券 | 暂不生成；必须由 promotion 和 Money 合同计算 |
| 限时倒计时 | 没有有效起止时间和恢复语义时不显示 |
| 到达时间、次日达 | 只展示 Shopping/Logistics 可证明的履约信息 |
| 仅剩几件、抢购中 | 只使用真实库存状态，不用动画制造稀缺 |
| 官方认证、功效、产地 | 只使用 SchatPhone 已审定的虚构事实，避免医疗或官方暗示 |
| 抽签、会员专享 | 未实现资格、申请与结果合同时只作为编辑预告，不做可执行按钮 |

建议后续冻结以下内容记录，而不是把内容硬编码在组件中：

- Campaign：`serviceKey`、双语标题、媒体槽、CTA、商品集合、展示时段、状态；
- Collection：双语名称、排序、封面、商品 ID、编辑说明；
- Product media：用途、比例、焦点、安全区、alt、locale 策略和版本；
- Product detail section：类型、标题、媒体、结构化事实和顺序；
- Merchandising block：首页位置、展示规则、fallback 和内容来源；
- Motion asset：poster frame、时长、循环策略、静态替代和 reduced-motion 行为。

## 7. 六店装修指南

### 7.1 Coupang / `schat_mall` / `city_market`

#### 定位与视觉论点

`快速、密集、可信到达`。页面应像高效率综合商城，而不是品牌画册。白色和浅灰承担大面积信息底，红、蓝、黄分别承担动作、履约和活动识别；颜色不得铺满所有容器。

#### Home 内容顺序

1. 紧凑顶栏：返回、品牌、搜索、收藏、购物袋；搜索是第一主入口。
2. 4 组 Hero campaign：日常速购、周末补给、家居焕新、礼赠集合。
3. 履约与服务 strip：只有真实可证明的配送/报价信息。
4. 8 项快速分类图形入口。
5. “今日编辑优惠”横向商品 rail；无真实折扣时不用划线价。
6. 高频补货模块：根据真实最近浏览/购买记录出现，否则显示编辑补给组合。
7. 两张横向滚动广告：家居补给、穿搭与护理。
8. 综合商品流：允许高密度两列与分组标题，不使用同尺寸卡片铺满全页。
9. 竖版活动海报 rail：生日、旅行、雨季等生活场景。
10. 最近浏览、订单和服务入口。

#### 专题与详情

- Category 强调筛选、排序和快速浏览；编辑故事保持短。
- Product Detail 首屏优先商品、价格、状态、规格和加购；长详情强调功能、尺寸和使用场景。
- 可以提供“同类比较”表，但只能比较当前虚构商品的结构化字段。
- Reorder 是独立管理页，不与新用户首页强绑定。

#### 动效语法

- `180-240ms` 的快速 snap、搜索展开和商品加入反馈。
- 加购成功由缩略图轻量缩放至购物袋方向，不做长距离抛物线。
- 履约状态使用一次进度扫过；无真实状态变化时保持静止。

#### 专属增强素材 8 个

- 4 个日常补货组合条幅；
- 2 个服务/履约图解；
- 2 个同类比较背景板。

禁止：把页面做成纯红色促销墙、伪造闪购倒计时、用大量角标覆盖商品主体。

### 7.2 29CM / `nova_digital` / `tech_catalog`

#### 定位与视觉论点

`编辑、留白、值得关注`。黑、白、暖灰构成杂志基底，橙色只用于动作与章节定位。产品并非普通白底列表，而是被设计说明、材质、空间和编辑主题组织。

#### Home 内容顺序

1. 低高度编辑 masthead：品牌、期号/主题、搜索和购物袋。
2. 1 张主封面加 3 张可切换 Hero，使用不对称留白和稳定标题区域。
3. 本期目录：Tech、Living Design、Fashion Objects、Gifts。
4. “编辑选择”大图与小图错落货架。
5. 横向 Issue cover rail，进入独立专题。
6. Design Note：一件商品加材料/设计语义，不显示虚构设计师背书。
7. Objects in Use：使用环境与商品组合。
8. 新品网格；卡片允许更大图片、更少促销标签。
9. 品牌/系列索引；只有存在真实虚构品牌记录时才可点击。
10. 收藏、最近浏览与订单入口。

#### 专题与详情

- Editorial 页面像可购物杂志：封面、章节、图片说明、商品插入和结尾目录。

## 8. 动效系统

### 8.1 共享动效等级

| 等级 | 使用位置 | 规则 |
| --- | --- | --- |
| M0 静态 | 价格、订单真相、表单、无障碍 fallback | 不依赖动画理解状态 |
| M1 微交互 | 收藏、加购、tab、筛选、按钮反馈 | `150-240ms`，清楚反馈，不改变布局尺寸 |
| M2 导航连续性 | 页面进入、返回、详情媒体切换 | `220-420ms`，保持来源与目标空间关系 |
| M3 品牌媒体 | Hero、Lookbook、房间热点、质地 loop | 少量使用；有暂停、poster frame 和 reduced-motion 替代 |

### 8.2 Carousel 与滚动广告

- 自动轮播只用于 Hero，默认 5-7 秒；用户触摸、键盘聚焦或鼠标悬停时暂停。
- 指示器必须可点击并说明当前位置；不能只依赖模糊渐变暗示。
- rail 使用原生横向滚动和 scroll snap，支持触摸、触控板、滚轮转译、键盘与可见箭头。
- 页面离开、App 后台或元素离开视口后停止计时与视频。
- reduced-motion 下取消自动切换、视差和遮罩动画，仍保留手动浏览与完整状态。

### 8.3 性能规则

- 只动画 `transform` 和 `opacity`；不连续动画 width、height、top 或大面积 blur。
- 首屏仅预载当前 Hero 和下一张；其余海报、详情与视频按接近视口时加载。
- 所有固定比例媒体预留尺寸，目标 `CLS < 0.1`。
- 单个移动 Hero runtime 建议不超过 `280 KB`；商品卡图不超过 `120 KB`；PDP 主图不超过 `240 KB`。
- 3-6 秒静音 loop 建议不超过 `1.5 MB`，同时提供 WebP/AVIF poster frame；不使用 GIF。
- 同一图像生成响应式 `srcset` 派生，不把每个宽度计作新的创意生成任务。

## 9. 响应式、无障碍与状态

### 9.1 视口策略

| 视口 | 构图要求 |
| --- | --- |
| `320-430px` 手机 | 单列内容带、两列商品网格、1.15 张 rail 暗示、44px 最小触控区 |
| `431-767px` 大手机/小平板 | 2-3 列商品、双栏编辑模块、Hero 保留 3:4 构图 |
| `768-1199px` | 双区域 Home、3-4 列商品、专题图文并置但不做营销式左右分屏 Hero |
| `1200px+` | 最大内容宽度约 1440px，4-5 列商品，宽屏 Hero 使用独立 16:9 构图；不能机械拉伸手机页 |

- 字号不随 viewport 连续缩放，标题使用离散断点。
- 不允许水平页面溢出；只有明确 rail 可横向滚动。
- 长品牌名、双语标题和价格必须在容器内换行或截断，不遮挡相邻操作。
- 安全区、底部导航和 sticky 购买条不得互相覆盖。

### 9.2 无障碍

- 正文对比度至少 `4.5:1`，大字至少 `3:1`；品牌色不自动等于可读前景色。
- 所有 icon-only 控件有可访问名称、可见焦点和稳定 hit area。
- 海报 alt 描述活动主题和目的，不复述装饰背景；纯装饰纹理使用空 alt。
- 自动媒体提供暂停；视频无声音依赖；动画不能成为唯一状态线索。
- 焦点进入 carousel 后，键盘左右键只控制当前 rail，不劫持整个页面。
- 商品状态不能只用颜色；同时展示文字或图标。

### 9.3 必测状态矩阵

| 页面 | 状态 |
| --- | --- |
| Home | 正常、首屏加载、单个 campaign 缺失、全媒体降级、离线/错误 |
| Search | 初始、输入中、有结果、无结果、筛选后为空、错误 |
| Category/Collection | 正常、排序、筛选、空集合、失效专题 |
| Product Detail | 在售、规格未选、低库存/售罄、媒体缺失、价格不可报价 |
| Saved/Recent | 空、部分商品失效、恢复到来源 |
| Bag/Checkout | 空、数量变化、失效商品、报价变化、提交中、失败、成功 |
| Orders/Logistics | 空、处理中、发货、到达、取消/异常、来源返回 |
| Motion | 正常、暂停、后台恢复、reduced-motion、低性能静态替代 |

| `ratio` / dimensions | 原始比例与尺寸 |
| `safeZone` / focalPoint | 响应式裁切依据 |
| `localeStrategy` | 无字、固定英文、zh/en 双版本等 |
| `prompt` / generator / quality / date | 生成追溯 |
| `sourceAndRights` | 参考来源与许可边界 |
| `selectionStatus` | candidate、accepted、rejected、retired |
| `selectionReason` | 选择/淘汰原因 |
| `sha256` / bytes | 发布与跨机器验证 |
| `altZh` / `altEn` | 可访问语义 |
| `motionFallback` | loop 的静态替代 |
| `lifecycle` | evergreen、seasonal、scheduled、archived |

命名示例：

```text
campaign-weekend-restock-hero-mobile-01.webp
campaign-weekend-restock-hero-wide-01.webp
collection-small-space-work-banner-01.webp
shopping-seed-nordhus-chair-main-01.webp
shopping-seed-nordhus-chair-detail-material-01.webp
shopping-seed-nordhus-chair-context-room-01.webp
state-empty-bag-01.webp
```

## 12. 分批执行建议

| 批次 | 内容 | 正式数量 | 验收重点 |
| --- | --- | ---: | --- |
| S0 | 冻结六店 IA、内容字段、页面 wireframe 和槽位 manifest | 0 | 不生成会因页面改动而报废的媒体 |
| S1 | 每店 5 个校准样例：手机 Hero、宽屏 Hero、商品主图、PDP 细节、专题卡 | 仅候选 | 六店差异、裁切、文字安全区和页面真实感 |
| S2 | 六店 Home media 基础包 | 216 | Hero/rail/海报在真实页面中的节奏与首屏性能 |
| S3 | 当前 31 个稳定 SKU 的完整 5 槽媒体 | 155 | 商品识别、详情连续性、同店一致性 |
| S4 | 剩余 41 个 SKU 获批并落地后的完整 5 槽媒体 | 205 | 数据合同先于生成，避免废图 |
| S5 | Campaign story、editorial、motion、states 与品牌增强 | 236 | 专题长页、降级、reduced-motion 和异常状态 |
| **合计** | 完整正式库 | **812** | 候选与派生文件不计入 |

每批必须先通过单店完整链路再并行扩展：Home -> Campaign/Collection -> Product Detail -> Bag -> Checkout -> Order。不得先生成六店全部素材，再发现页面槽位和裁切逻辑不成立。

## 13. 素材验收门槛

### 13.1 单图

- 主题、商品、店铺和 placement 语义一致；
- 主体结构合理，无重复部件、错误手指、不可用家具、失真食物或矛盾包装；
- 无官方 Logo、真实包装、可读乱码、价格、水印、二维码或合作暗示；
- 在目标最小显示尺寸仍能识别；
- 安全区、焦点和移动/宽屏裁切通过；
- alt 与图像表达一致；
- accepted master、runtime derivative 和 hash 可追溯。

### 13.2 同店

- 白平衡、光线、材质、镜头高度和阴影方向形成稳定语法；
- Home、专题和 PDP 像同一品牌，但不要求所有图片使用同一背景；
- 商品主体与广告叙事有明确层级，不让装饰吞没商品；
- 至少能通过媒体构图而非 Logo 分辨店铺。

### 13.3 六店

- 任意移除 Logo 后，六店仍能通过内容顺序、比例、材料和动效被区分；
- 不出现六套相同 4-card grid 只换颜色的结果；
- 不使用一个统一的 3D 玩具、柔光静物或单色渐变风格覆盖所有店；
- Marketplace 与 specialty store 的信息密度和叙事节奏明显不同。

## 14. UI 完成定义

单店只有同时满足以下条件，才能称为“装修完成”：

- [ ] 首屏能在 3 秒内识别店铺定位、主要活动和下一步入口；
- [ ] Home 至少有 7 个有不同内容职责的模块，不靠嵌套卡片堆数量；
- [ ] 至少 4 个 Hero campaign、6 个 rolling ad、6 个竖版海报和 3 个可打开专题页；
- [ ] 12 个商品均有 5 槽媒体，详情页不是放大的商品卡；
- [ ] Search、Category、Collection、Saved、Bag、Checkout、Orders 与 Logistics 有明确页面深度；
- [ ] 加载、空、错误、售罄、失效专题和图片失败均有品牌化但可理解的状态；
- [ ] 动效体现店铺语法且 reduced-motion 完整可用；
- [ ] 手机、宽屏、键盘、触控、焦点、overflow 和安全区通过；
- [ ] 首屏媒体预算、lazy loading 和布局预留通过；
- [ ] 没有伪造销量、折扣、倒计时、评价、资格、配送承诺和品牌合作；
- [ ] 所有商品、购物袋、订单和可见历史仍按 `serviceKey` 隔离；
- [ ] 用户视觉验收和命名设备验收分别有证据，不以自动测试代替主观接受。

## 15. 实施前需要冻结的决策

1. 六店第一轮是否直接采用 12 SKU，还是先用当前 31 个稳定商品完成 UI 链路。
2. Campaign、Collection、Product Detail section 和 Motion asset 的最小内容合同。
3. 商品规格、尺寸、颜色、成分、保存、材料等字段按品类如何建模。
4. 专题页和详情页的 route/query 形式及返回上下文。
5. 哪些固定 Editorial 允许图片内艺术字，以及 zh/en 的版本策略。
6. 当前报价、promotion、库存、物流和未来 review 数据的显示边界。
7. 六店 S1 校准候选的用户选择顺序；在方向获批前不批量生产 812 个母版。

本指南批准后，最小安全实施切片应是 S0 + S1：先用真实页面原型证明六店 IA 和 30 个风格校准候选，再选择一家店完成全链路。它不能被解释为自动批准大批量生图、依赖安装、业务 schema 迁移或 812 个素材的一次性交付。
