# SchatPhone Project Iteration Plan

Updated: 2026-08-26

Integrated baseline: `f06a575`

This is long-range sequencing guidance. It is not an implementation board and cannot override `docs/roadmap/TODO_ROADMAP.md`.

## 1. Current Phase

Current phase:

> Integrated product preview, durable continuity closure, and release proof

The project has already passed prototype viability, basic cross-module integration, first persistence/recovery architecture, initial event/runtime infrastructure, and the first broad installed-App shell portfolio. The immediate work is to make those foundations trustworthy and demonstrable.

## 2. Current Sequence

### Phase A: Continuity Closure

- complete `CMG-08`, then `CMG-09` and `CMG-10`;
- preserve canonical history without unbounded prompt/list cost;
- prove failure, reopen, backup/restore, and migration behavior.

### Phase B: Product Preview Proof

- install and relaunch the PWA;
- verify the first-use AI/Chat loop and backup round trip;
- run named physical-device checks for safe areas, keyboard, touch, file import/export, media, and navigation;
- verify external repository/environment protections.

### Phase C: Focused Hardening

- fix only problems observed during product-preview proof;
- run World Pack true-device checks where they share the release matrix;
- promote one exact owner or product-depth slice at a time.

### Phase D: Controlled Expansion

Only after explicit roadmap promotion:

- S1 shell to S2 owner or S3 event chain;
- production Mini Scene trigger/HTML/media stages;
- personal R2 backup implementation;
- deeper Gallery, Assets, Stock, commerce settlement, Map exploration, or world evolution;
- one measured hotspot/adapter/type slice.

## 3. Promotion Rules

1. every implementation slice must have one roadmap or user-authorized scope;
2. parent completion never erases child milestone status;
3. package handoffs retain task-level evidence and exclusions;
4. product behavior, dependency migration, and broad refactoring remain separate;
5. proposals, prototypes, and external assessments do not become work until promoted;
6. true-device, hosted, provider, and physical-world evidence must be named rather than implied.

## 4. Deferred Decisions

- closed-page autonomous event generation;
- production Cheats authority;
- World Setting W2/W3 and multi-save/sync semantics;
- production push tenancy/authentication;
- personal R2 implementation timing;
- broader automatic high-impact relationship/world evolution;
- full-app TypeScript migration or framework rewrite.

## 5. Status Ownership

- roadmap: priority and authorization;
- package handoff: detailed domain progress;
- contract: behavior and ownership;
- this file: long-range sequencing only.
