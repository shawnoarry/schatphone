## 1. Current Product Stage

SchatPhone is an integrated local-first virtual phone and AI life-simulation product. It has moved beyond prototype and broad foundation building into product-preview hardening, durable continuity governance, hosted/PWA proof, and focused completion of already integrated modules.

The project is not yet a production-hardened final release. Named physical-device evidence, installed-PWA/relaunch proof, external repository/environment protections, several provider-specific smokes, and selected secondary product loops remain open.

## 2. Current Execution Order

1. Complete the remaining hosted product proof: installed PWA, relaunch, backup round trip, external protections, and named true-device evidence.
2. Preserve the completed `CMG-00` through `CMG-10` continuity contracts while fixing only failures found by product-preview proof.
3. Run World Pack true-device validation only where it overlaps the release device matrix.

The user-promoted World Setting W2 single-world identity/version slice is complete. Hotspot decomposition, incremental typing, personal R2/Worker, production push, broader Gallery/non-Book migration, World Setting W3 switching, and secondary-module expansion remain on hold until the first usable product preview unless the user explicitly changes priority.

## 4. What Users Can Do Now

- configure a user-owned AI provider and use persistent role, service, and group Chat flows;
- manage Contacts, roles, relationship facts/memories, Book/WorldBook content, and reviewed World Pack capabilities;
- prepare any authored current world from Settings, run one explicit model check, confirm a reproducible rules version, detect later WorldBook changes, and restore the previous version without rewriting already-started events;
- use Map journeys, Calendar/Agenda Journey scheduling, Reminders, Phone, Gallery, Camera, Music, TTS preview, weather, and system notifications;
- configure real event frequency, app permissions, supported presentation, and foreground checks from the dedicated mobile Settings event page;
- use a production Work Hub when the current world formally supplies valid organization authority, review ordinary notices/tasks/proposals, explicitly decide or report status, and send accepted time proposals to Calendar for a separate Save;
- receive a reproducible world-neutral Work Hub schedule-change event, accept, request adjustment, or decline it in Work Hub, and keep the previous Calendar commitment until an explicit review and Save replaces that same event with retained source lineage;
- continue an explicitly saved production schedule change through one Agenda notification, explicit Map departure/arrival, and explicit Activity Session start while stale or changed revisions fail closed;
- use `生活志 / Chronicle` to review verified Work Hub, Calendar, Agenda Journey, Map, and Activity Session traces by date/source, write or edit personal diary entries, retain prose across broken links, and return to exact source owners without an AI call;
- shop across independent Shopping storefronts and Food Delivery entries with Wallet-backed checkout, receipts, orders, service support, and source-return flows;
- use the installed S1 shell portfolio for Mail, Browser, Community, Healthcare, Housing, Workplace, Fandom, Tickets, Travel, Intercity, Creator Rights, Parcel, and Career without those previews falsely claiming production owner actions;
- export and restore complete local backups under the current release-local recovery contract;
- run the same repository through gated lint, unit, production build, dependency-audit, and full Playwright CI/deployment workflows.

## 5. What Is Not Finished

- no named complete physical-device matrix or installed-PWA/relaunch acceptance;
- no production-grade authenticated push backend or closed-page autonomous simulation;
- no automatic personal R2 backup implementation despite the accepted architecture direction;
- no general multi-world W3 persistence and switching;
- Contacts V3-4C now provides the archive-first user flow, archived Wallet payee suspension/restore, and replacement of the legacy active-person direct-delete entry; broader V3-5 consumer adoption remains gated;
- no production Mini Scene trigger/HTML/media expansion; optional complete-scene retention and retained-history management are integrated under completed `CMG-08`;
- no AI recall, automatic diary generation, free-text fact extraction, automatic organization membership from Contacts text/preview/model output, inferred attendance/completion, or downstream Wallet/relationship/public consequence chain;
- no claim that every S1 shell has an S2 owner Store or S3 Event Runtime chain;
- no broad hotspot rewrite, full TypeScript migration, or universal coverage threshold;
- Assets, Stock, refunds, tracking shares, and several provider/device-specific loops remain shallower than the strongest product areas.

## 6. Release Posture

PR CI and main Pages deployment definitions run separate production/full audits, lint, unit tests, production build, and one full Playwright collection. Hosted GitHub Pages, Vercel, and Cloudflare baselines plus direct/restricted-provider Chat smokes are recorded in the roadmap and architecture handoff.

This proves a strong integrated browser baseline. It does not prove external branch protections, every provider, installed-PWA behavior, OS permission behavior, weak-network recovery, or physical-device ergonomics.

## 7. Status Preservation Rule
