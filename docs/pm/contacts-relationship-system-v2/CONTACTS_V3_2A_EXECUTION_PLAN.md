## 1. 最终要得到什么

联系人中的个人页面应由一张可扩展资料卡生成：

- 世界观可以建议默认类目和字段；
- 用户可以调整世界模板，也可以只给某个人增加内容；
- 用户可以直接填写，也可以粘贴整段人物描述让系统帮助归类；
- 所有确认结果继续保存成同一种 Contacts 人物资料；
- Chat、事件和 Work Hub 后续只读取各自获准使用的资料，不再要求用户重复填写身份。

本施工单允许逐步试用和调整页面表现，但不允许在调整过程中另造第二套人物存档。

## 2. 已经存在的基础

- Contacts 已经统一管理 Self Profile、Main Role、Supporting Role 和 World NPC 的人物资料行为；
- 人物 ID、资料版本、Chat 绑定、归档恢复和备份兼容已经受到保护；
- WorldBook 已经能保存带版本的世界人物模板；
- Contacts 已经能套用模板、填写具体值、设置可见范围和复核模板变化；
- AI 已经只能生成待确认字段草稿，不能自动保存；
- 当前世界模板、世界观生成草稿、动态个人页、人物专属扩展和文字归类保存已经使用同一套类目/字段结构；正式 Chat、Event Runtime 和 Work Hub 只读取各自获准的精简投影。

## 3. 可以边做边调整的内容

下面这些属于体验选择，可以在真实页面出现后继续调整：

- 类目是默认展开还是收起；
- 每个类目摘要显示几项内容；
- “添加资料”“补充资料”等按钮名称；
- 类目卡片的视觉样式、图标和间距；
- 空类目的提示方式；
- 从个人页哪个位置进入“从一段描述补充资料”。

这些调整不应迫使资料迁移或改变事件条件。

## 4. 不能随意改变的底线

1. 世界模板、人物自定义和文字归类最终使用同一套资料卡格式；
2. 字段改名不能让 Chat、事件或 Work Hub 失去原来的资料引用；
3. AI 和文字归类结果必须经过用户复核，不能自动覆盖；
4. 好感、疲劳、热度、余额、工作进度和事件结果不进入 Contacts；
5. Contacts 保存稳定人物身份，其他功能继续保存自己的动态数据；
6. 旧人物、旧模板、人物 ID、Chat 记录、归档和备份必须继续可读；
7. 个人详情页扩展现有页面，不增加第二张“新版人设页”。
8. Work Hub 权限确认主要约束用户自己的 Self Profile；其他角色的职业、组织和职位可以作为稳定人物设定保存，不要求角色逐个进入 Work Hub 申报。
9. 人物层级与关系标签分开：主要/次要/世界 NPC 决定参与深度，家人/朋友/同事等标签描述关系，不互相替代。
10. 旧 NPC 不根据聊天次数、资料完整度或模型推断自动改成次要角色；任何层级调整都必须由用户明确确认并保留人物历史。

## 5. 联系人实施顺序

### CARD-1 — 类目兼容底座 — `DONE 2026-08-27`

用户暂时看不到页面变化。

要做：

- 在现有模板中加入可排序的资料类目；
- 字段可以归属某个类目；
- 旧模板自动进入默认类目；
- 类目和字段 ID 由系统稳定保存；
- 增加规范化、复制、旧数据兼容和上限测试。

完成标准：旧模板和旧人物值读取结果不变，新模板能稳定保存多个类目，重复或无效 ID 安全处理。

完成结果：

- 现有模板现在可以保存排序后的 `categories`；
- 每个字段保存稳定 `categoryId`；
- 有字段但没有类目的旧模板会自动得到默认类目；
- 指向不存在类目的旧字段会安全进入第一个有效类目；
- 重复类目 ID 会被去重，类目数量有安全上限；
- 模板复制会独立复制类目和字段，修改副本不会污染原模板；
- 没有改页面、人物值、模板 ID、模板版本规则、Chat 绑定或备份外壳。

### ROLE-0 — 四类人物产品决定 — `DONE 2026-08-27`

已确认：

- Self Profile 是用户自己的特殊身份，不进入其他人物的升级链；
- 其他人物分为 Main Role、Supporting Role 和 World NPC；
- 人物升级链为 `World NPC -> Supporting Role -> Main Role`，允许用户明确跨级升级；
- 升级必须保留人物 ID、资料、Chat 绑定与历史、世界/组织引用、事件来源、归档和备份；
- 家人、朋友、同事等是可多选关系标签，不是人物层级；
- 现有 `npc` 内部值继续作为 World NPC 的兼容值，不能自动重分旧人物。

### ROLE-1 — 四类人物兼容底座 — `DONE 2026-08-27`

用户暂时不会看到联系人页面重排。

要做：

- 在现有人物类型中新增稳定的 `supporting_role`，保留 `npc` 作为 World NPC 的兼容值；
- 让资料模板的适用人物范围、Contacts Profile Owner、角色绑定兼容层和备份读取认识四类人物；
- 保留旧 `isMain` 二元兼容字段，但以正式人物类型为准，`Supporting Role` 和 `World NPC` 都不能被误判成主要角色；
- 为次要角色建立“可反复出现、可 Chat、可参与事件、可保留轻量记忆，但不默认完整关系成长”的安全能力默认值；
- 保持已有 NPC 的能力和 Chat 绑定，不因本次类型扩展自动关闭或重建；
- 保留 World NPC 直接升级为 Main Role 的旧入口，同时为后续 World NPC -> Supporting Role -> Main Role 页面流程准备统一升级规则；
- 增加旧记录、四类规范化、能力默认值、升级保留和备份往返测试。

完成标准：现有三类存档读取结果不变；新建次要角色能被稳定保存、复制、恢复和模板筛选；任何升级都保持同一人物 ID 和既有绑定；本步骤不改联系人首页视觉分组。

完成结果：

- 新增正式 `supporting_role`，现有 `npc` 继续表示 World NPC；
- 次要角色默认可进入 Chat、世界事件和社交内容，可保留轻量记忆，但不默认开启完整关系成长和路线推进；
- 正式 `entityType` 优先于旧 `isMain`，次要角色不会被 `isMain=false` 误降为 World NPC；
- Chat 绑定契约、模板适用范围、Contacts Profile Owner、存储和备份恢复均可保留次要角色；
- 新增 World NPC -> Supporting Role、Supporting Role -> Main Role，并保留直接 World NPC -> Main Role；
- 所有升级保持同一人物 ID、资料值、Chat 绑定和既有历史；
- 联系人首页暂时把次要角色放入原次级人物列表，Role Hub 和 Chat Directory 显示正确类型名称，没有提前进行四区视觉重排。

### CARD-2 — 字段用途与填写方式 — `DONE 2026-08-27`

用户暂时只会在模板管理中看到有限变化。

要做：

- 在现有五种填写方式基础上，确认首批增加的日期、是/否、组织引用等方式；
- 所有字段首先都是正常人物资料，不设置“无用”或“仅展示”分类；
- 在基础人物资料之外，为字段增加可叠加的使用范围：Chat 上下文、事件判断、Work Hub 角色/组织匹配、公开内容；
- 旧字段继续作为正常人物资料，但不自动获得新的事件判断、工作匹配或公开权限；
- 区分人物类型：Self Profile 的组织字段只能匹配用户工作区，Main Role/Supporting Role/World NPC 的组织字段可以直接表达角色设定；
- 自定义字段使用系统生成的稳定 ID，普通用户不必填写内部名称。

完成标准：字段改显示名后稳定 ID 不变；每项字段至少保留人物资料价值；不合适的填写方式或额外使用范围组合会被阻止或安全降级。

落地结果：

- 保留原有短文本、长文本、单选、多选标签和人物引用，并新增日期、是/否、组织引用三种正式填写方式；数值、公式和周期计算仍不进入本轮；
- 每个字段天然属于人物资料，额外用途使用 `chat_context`、`event_eligibility`、`work_hub_matching`、`public_content` 四个可叠加标记；
- 旧模板字段默认用途为空，不会因升级自动进入事件判断、工作匹配或公开内容；
- 长文本会安全移除事件判断和 Work Hub 匹配用途，日期和是/否会移除 Work Hub 角色/组织匹配用途，避免把不适合精确匹配的内容误当成权限或身份依据；
- 新增系统管理的自定义字段 ID 生成入口；字段显示名变化不会改变已经保存的字段 ID；
- Contacts 现有填写页可编辑日期、是/否和组织引用；是/否回看时显示自然语言，AI 草稿中的日期和是/否必须通过格式校验才会进入待填写草稿；
- Self Profile 的组织引用只提供 Work Hub 匹配线索，不能自动授予用户工作区权限；其他人物的组织引用可直接保存为已确认角色设定；
- 现有模板版本、联系人资料值、可见范围、模板适配草稿和存储恢复链路保持兼容，没有迁移 Event Runtime、Work Hub 或正式 Chat 消费者。

### CARD-3 — WorldBook 手动资料卡编辑 — `DONE 2026-08-27`

要做：

- 在现有世界人物模板管理中增加类目；
- 支持新增、改名、排序和删除类目；
- 支持字段在类目之间移动；
- 删除类目时必须先决定字段去向；
- 继续使用现有模板 ID、版本和保存方式。

完成标准：用户不用 AI 就能制作一张完整世界资料卡，取消或保存失败不会改变旧模板。

落地结果：

- 继续使用现有 WorldBook 人物模板入口和现有模板格式，没有新增第二套页面或第二套资料格式；
- 可从空白资料卡开始，也可编辑现有模板；取消新建不会留下空模板，取消旧模板修改不会改变原版本；
- 类目支持新增、改名、排序和删除；删除含字段类目前必须选择字段搬迁目标；
- 字段支持新增、改名、排序、删除和跨类目移动，并可配置填写方式、选项、说明、可见范围、适用人物、额外用途、必填与推荐状态；
- 类目和字段使用系统生成的稳定 ID，显示名称改变不会换 ID；保存现有模板时生成新版本，旧联系人值仍可按原字段 ID 延续；
- 桌面与 390px 手机宽度均可完成新建、取消、保存和重新打开，未开启独立美化任务。

### CARD-4 — 个人页动态资料卡 — `DONE 2026-08-27`

要做：

- 在现有个人详情页按类目生成资料区块；
- 查看状态只显示易读摘要和自然语言补充提示，不显示 `3/4` 一类完成度数字；
- 编辑状态显示该类目的完整表单；
- 保留关系、记忆、关联活动和管理等原有独立区域；
- 旧平面模板显示在默认资料区块中。

完成标准：新增类目不需要新增页面或专用代码；桌面和手机都能查看、编辑、取消和重新打开。

落地结果：

- “人物资料”默认先显示阅读状态，用户明确点击编辑后才展开完整表单；
- 阅读状态按 WorldBook 类目动态生成区块，只展开已填写内容，未填写的必填或推荐项改用“请补充 / 建议补充……”等自然提示；
- 页面不显示 `3/4` 一类完成度数字，也不把人物资料做成任务清单；
- 编辑状态沿用同一套类目和字段结构，继续支持现有填写控件、可见范围、AI 草稿、模板适配、明确保存与取消；
- 旧平面模板自动进入“基本资料 / General”，人物原有但不属于当前模板的值继续进入“补充资料”并保留；
- 保存后回到阅读状态，重新编辑能读到已保存值，取消不会泄漏未保存修改；
- 关系、记忆、人物详情、关联活动、Chat 绑定和管理区继续独立存在，没有被资料表单吞并；
- Chromium 桌面与模拟 Pixel 5 均已覆盖默认阅读、进入编辑、保存、重新编辑、取消和无横向溢出，没有开启独立美化任务。

### CARD-5 — 人物专属扩展 — `DONE 2026-08-27`

要做：

- 从个人页增加人物专属类目或字段；
- 明确选择“只给这个人物”或“加入当前世界模板”；
- 世界模板更新时保留人物专属内容；
- 模板差异继续通过现有复核逻辑处理。

完成标准：一个人物的特殊资料不会意外出现在其他人物上，也可以由用户主动复用。

落地结果：

- 每个人物档案可保存自己的 `profileExtensions.categories` 和 `profileExtensions.fields`，继续由 Contacts Profile Owner、现有本地存储与完整备份链路管理，没有新增 Store 或第二套备注格式；
- 旧人物读取时自动得到空扩展；个人页把世界模板、人物专属结构和旧的未知资料值合并为同一张阅读/编辑资料卡；
- “添加资料”先进入本次编辑草稿，外层取消不会修改人物，也不会修改世界模板；
- 用户可明确选择“只给这个人物”或“加入当前世界模板”；只有后者在正式保存时生成一次模板新版本；
- 人物专属字段可放入世界模板已有类目，也可放入新建的人物专属类目，并继续使用短文本、长文本、选择、标签、日期、是/否、人物引用和组织引用；
- 人物专属内容不会传播到其他人物；世界模板升版也不会替其他人物自动填值，其他人物仍保持原模板版本并进入现有模板复核链路；
- 后续世界模板适配会继续保留人物专属内容，稳定 ID、人物值、Chat 绑定和备份格式保持兼容。

### CARD-6 — 世界观生成资料卡草稿 — `DONE 2026-08-27`

要做：

- 从当前 WorldBook 和世界包规则生成类目、字段、选项和用途建议；
- 先保证手动规则路径可用，再接可选 AI 草稿；
- 建议始终可以增删改、排序和取消；
- 只有明确保存才产生世界模板新版本。

完成标准：不同世界可以得到不同的可编辑建议；无 AI、AI 失败和取消都不阻塞手动创建。

落地结果：

- WorldBook 的当前世界模板区域新增“根据当前世界生成建议”和“用 AI 生成建议”，继续复用现有资料卡编辑器，没有新增第二套模板页面或格式；
- 不依赖 AI 的规则生成器读取当前 WorldBook 文本、当前/已启用世界包及其明确推荐特征，可区分现代、偶像娱乐、校园、企业家族、都市怪谈、灾后生存和仙侠方向；
- 通用身份底座稳定使用 `occupation`、`affiliation` 和 `public_identity`，同一输入重复生成时字段 ID 保持一致；
- 世界包的“可适配”特征不会被误当成当前世界事实，避免现代世界无缘无故混入偶像、校园或财阀字段；
- AI 只返回类目、字段、类型、选项、用途、可见范围和适用人物建议；无效类型、用途、人物类型和可见范围会安全过滤或降级，解析失败不产生草稿；
- 规则和 AI 建议都进入可增删改、排序和取消的现有编辑草稿；取消不会改变模板数量或内容，只有明确保存才创建一个当前世界 v1 模板；
- AI 失败只显示提示，不关闭或破坏已打开的规则/手动草稿，也不阻塞手动新建；
- 本步骤不填写任何人物值，不创建人物资料修订、组织权限、事件、动态数值、好感、余额、疲劳或进度。

### PERSONA-1 — 整段文字归类草稿 — `DONE 2026-08-27`

要做：

- 把用户文本匹配到当前资料卡已有字段；
- 无法匹配的内容保留原文，并可建议新增字段；
- 已有值冲突时同时展示旧值和候选值；
- 归类结果只存在于复核草稿中。

完成标准：未识别内容不丢失，取消和解析失败不改变人物资料。

落地结果：

- 在 Contacts 现有“世界资料卡”页加入整段人物描述入口，与资料卡编辑流程互斥，不增加第二个页面或第二种人物数据格式；
- 分类契约保留精确原文段，并生成不可变、绑定人物/世界/模板/资料版本的复核草稿；
- 结果固定呈现匹配字段、新字段建议、冲突和未归类原文四组，已确认值与候选值并排显示，不静默选择或覆盖；
- 关闭、解析失败、人物切换、资料版本变化和过期异步响应都清理草稿或安全失效；
- 成功归类、关闭和解析失败均不会改变 `profileValues`、`templateLink` 或 `revision`，本步骤没有接受或保存按钮。

### PERSONA-2 — 复核并保存人物资料 — `DONE 2026-08-27`

要做：

- 支持逐项接受、修改、忽略；
- 保存前再次检查世界、模板和人物资料版本；
- 通过 Contacts Profile Owner 写入一次新的资料版本；
- 保存失败完整恢复旧资料。

完成标准：手动填写和文字归类得到相同的联系人资料结构，下游功能不需要区分资料来源。

落地结果：

- 每一行必须明确接受或忽略；接受项可以在保存前修改值，新字段建议还可修改名称和可见范围，未处理行不能提交；
