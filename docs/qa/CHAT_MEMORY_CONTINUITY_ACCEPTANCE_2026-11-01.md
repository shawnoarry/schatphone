# 聊天记忆与角色连续性：修复和代验收

日期：2026-11-01

状态：`CHAT_MEMORY_CONTINUITY_DONE / DELEGATED_ACCEPTANCE_DONE`

## 验收结论

近期聊天内容能在重开后接到下一次对话；超出近期上下文窗口的重要内容，需要通过现有的“让 TA 记住”明确保留，再由角色记忆按话题选入请求。不会将所有历史消息自动提炼为长期记忆。

本轮修复了一个实际断点：同主题先后“记住”两条信息时，两条原始事实都保存着，但生成请求通常只得到最后一条摘要。例如先告诉角色“不喜欢医院的消毒水味”，再补充“去诊所会紧张，希望有人陪”，后续询问原因时可能只读到陪诊需求。

修复后，Relationship Runtime 在读取时保留最新说法，并按当前话题选取最多一条较早的已记住细节；明确标示先后及“后来的更正优先”。它不推断两句话的新合并结论，不改写已保存的摘要、事实或历史，也不增加关系数值。既有人工摘要优先，其他来源继续使用原有读取规则。

## 已验证场景

1. 发出普通消息并获得回复，刷新后下一次请求包含此前用户消息与角色回复；人设仍属于当前绑定角色。
2. 两条同主题信息分别执行“让 TA 记住”；重复执行同一消息不产生重复事实。
3. 再保存三条无关主题、发送多条普通消息，让原消息离开近期窗口；后续实际请求仍从记忆层取得相关的早期细节和最新补充。
4. 再次刷新、解锁、进入同一会话，记忆继续参与回复；原始聊天记录保持完整。
5. 切到第二个人物，读取其独立记忆和人设；第一人的内容不进入第二人的请求，反向亦然。
6. 归档后的记忆不参与默认召回；备份恢复前后仍能召回同一细节；读取不改变保存快照。
7. 同主题最多补充一条早期细节，沿用最多 3 组记忆 / 720 字符预算；重复文本去重，长内容仍受限。近期聊天沿用原有轮数及 12,000 字符窗口。
