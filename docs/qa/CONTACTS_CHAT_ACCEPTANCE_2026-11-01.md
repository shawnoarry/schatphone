# 联系人到聊天：代验收记录

日期：2026-11-01

状态：`CORE_FLOW_DELEGATED_ACCEPTANCE_DONE / LOCAL_ONLY / NOT_DEPLOYED`

用户先授权检查并直接修复联系人到聊天的流程，随后明确委托 Codex 代为体验验收。本记录关闭这一轮核心流程检查，不冒充用户亲自验收，也不把完整人物设定参与 AI 聊天或整个 Contacts 视觉重做声明为完成。

## 结果与修复

- 人物页增加“前往 Chat 添加 / 继续聊天”。未加入的人物在 Chat 联系人里预选并确认；取消返回同一人物且不建立绑定。已有会话直接复用。
- Chat 仍拥有绑定与会话；Contacts 的按钮只负责导航。自己、已归档人物、禁用聊天的人物不会成为新的添加候选；无效深链不建立绑定。
- 聊天详情的“联系人资料”现在打开当前人物，修正此前跳到整个聊天联系人列表的问题。
- 保留 Home 页码，并替换中间跳转记录，浏览器后退不会反复进入自动跳转页。
- 新建/编辑表单给人物 ID 和名字增加可见标签；验证错误显示在表单内部并保留到下次提交，修正被弹层遮住的反馈。档案管理说明不再声称普通编辑可以修改稳定 ID。
- 添加确认弹层补齐名称、字段标签、初始焦点、Tab 循环和 Escape 取消。

## 发现的能力缺口

通用资料卡可以保存、编辑、取消和重开，但没有世界绑定、模板版本和字段用途许可时，其字段不会进入 Chat 的身份投影。当前生成请求会使用基础身份和其他已允许的上下文，并不等于读取了全部资料卡。

本轮最初增加“通用资料卡字段应该进入请求”的断言，在桌面和模拟手机均失败。核对 `contacts-profile-projection.js`、`role-identity-projection.js` 与现行契约后，确认当前行为是明确的 fail-closed 规则，而非发送请求失败。没有通过放宽可见范围、自动标记旧字段或复制到简介来绕过它。人物页现在直接说明这一限制；最终 E2E 同时验证基础身份进入请求、未获许可的通用字段不进入请求。

这也是下一段角色连续性最先需要解决的问题：明确哪些已确认人设由用户允许用于聊天、如何支持无世界绑定的普通角色，并保持隐藏资料、模板修订与事件用途边界。当前 `CONTACTS-V3-2C` 仍为 `IN_PROGRESS`，`CONTACTS-V3-5` 未启动；无需用户重复完成本轮操作检查。
